[브라우저에서 실행](https://epicodix.github.io/astra-naval-lab/) · [유폭 장면 보기](https://epicodix.github.io/astra-naval-lab/simulator.html?preset=blast)

두 전함의 기동과 포격, 관통 피해와 탄약고 유폭을 브라우저에서 볼 수 있습니다. 사용자가 기능과 디테일을 제안하고, GPT Astra와 함께 함선 모델과 전투 로직을 구현했습니다.

## 기능

- 야마토와 아이오와의 함선 모델, 사거리와 조준 방향에 맞춰 움직이는 주포탑, 발사·재장전 연출
- 움직이는 함선을 겨냥하는 예측선, 포탄 산포와 비행 궤적, 실제 접촉 위치에 연결된 피격 판정
- 내부 관통 경로에 따른 기관·전력·급탄 설비 손상, 화재·침수와 손상통제
- 운용 인력·작업반 손실, 여러 피해에 분산되는 복구 역량과 같은 구획의 누적 구조 손상
- 함선별 철갑탄·고폭탄 선택, 탄종에 따라 달라지는 착탄 폭발·파편·발화
- 실제 내부 피해로 생기는 연료 누출·화재, 유한한 연료와 작업반에 따른 소화
- 탄약고 직격 또는 손상된 급탄 구역에서 번지는 화염에 의한 유폭
- 재생·일시정지, 시간 이동과 슬로모션으로 살펴보는 전투
- 실제 주포 발사 시점과 포구 방향에 맞춰 해면에 번지는 낮은 물안개·거품·압력 파문
- 자유 관찰·교전 관찰·함선 추적·탄착 추적으로 바꾸는 관찰 카메라

역사적 함선과 설비에서 착안한 **게임 모델**입니다. 관통·피해·유폭 확률은 실측 자료로 보정한 군사 시뮬레이션이 아니며, 실제 전투 결과를 예측하려는 목적이 아닙니다. 급소 관통은 적은 명중으로도 치명적인 결과를 만들 수 있지만, 단순히 명중 수가 쌓였다는 이유로 유폭시키지는 않습니다.

v12의 운용 인력·작업반 백분율은 남은 **가용 역량**을 나타내는 추상값이며 실제 사상자 수가 아닙니다. 내부를 관통한 포탄의 폭발·파편 경로에 노출된 구획에서 인력과 구조가 손상되고, 같은 구획의 구조가 약해지면 후속 피탄의 피해가 커집니다. 인력 손실은 전투 중 되돌아오지 않으며, 한정된 작업반을 소화·배수·냉각·설비 수리에 나눠 투입합니다. **탄약고 설비 수리 중지**는 탄약고 설비 수리만 중지합니다. 기본 대응도 남은 역량의 제약을 받으며, 운용 능력 상실에 따른 **전투 불능**은 침몰과 별도로 기록합니다.

v13에서는 철갑탄은 보호된 내부 관통에, 고폭탄은 큰 국소 폭발·파편·표면 화재에 유리하게 구분합니다. 외벽에서 막힌 고폭탄이 구획 이름만 보고 깊은 기관실이나 장약고를 손상시키지는 않습니다. 실제 내부 경로가 기관·보일러의 연료 계통에 도달하면 누출이 생기고, 점화원과 차단 능력 손실이 겹치면 화재로 번집니다. 연료는 유한하며 소화는 기존 작업반 역량을 함께 사용합니다. 연료 화재와 탄약고 유폭은 별개 사건이며, 연료·장약이 가득하다는 이유만으로 자동 폭발시키지 않습니다. 역사적 탄종 성능표를 재현한 피해 모델은 아닙니다.

v14는 초속·공기 저항·중력을 하나의 비행식에 연결합니다. 현재 거리와 이동 표적의 예상 위치에서 낮은 발사각과 비행 시간을 함께 구하고, 실제 포구·포신 방향에서 출발한 자유 비행을 외형 충돌 판정과 화면의 포탄·궤적 표시에 공통으로 사용합니다. 점선은 발사 시의 무산포 예상 궤적이고, 실선은 실제 지나온 길입니다. 선체는 디테일을 보여주기 위해 거리 대비 확대되므로 화면 전체가 실척 모형은 아닙니다. 함선의 노트와 포탄의 m/s는 시뮬레이션 시간 기준이며, 1× 재생은 실제 1초에 시뮬레이션 1초입니다. 항력은 사거리 범위에 맞춘 게임 근사로, 당대 탄도표의 모든 구간을 정확히 재현하지는 않습니다.

v15는 전투 중 함선별 **수리 집중 / 균형 운용 / 공격 집중**을 전환하는 게임 실험입니다. 같은 가용 인력을 사격과 피해 대응에 나눠 사용하며, 공격 집중은 장전과 조준 보정을 빠르게 하고 피해 대응을 약화합니다. 공격 집중의 피격 치명 위험 **×1.8**과 중심부 관통 치명성 **×1.5**는 실제 내부 급소에 도달했을 때의 조건부 상대 배수이며, 명중 또는 즉사 확률이 아닙니다. 일제사에는 공통 조준 오차와 포신별 거리·좌우 산포가 함께 적용됩니다. 안정적인 표적 추적은 초탄 조준 확신을 조금 높이고, 실제 관측한 탄착으로 다음 사격을 보정합니다. 선회·연기·사격 통제 손상은 조준 확신을 떨어뜨립니다. 명령은 현재 시점 이후에 적용되며 이미 발사한 포탄은 발사 당시 조건을 유지합니다. 명령 기록도 저장·재생하며, 시간을 되돌린 뒤 새 명령을 내리면 그 시점 이후의 명령을 새 선택으로 대체합니다.

v16은 주포 **9문이 각각 장전하고 준비된 순서대로 발사**합니다. 각 포는 발사 시점의 관측 속도와 평활한 선회율에서 이동 표적을 예측하고, 해당 포구의 비행 시간으로 조준점을 반복 계산합니다. 미래의 실제 함선 경로는 사용하지 않습니다. 과도했던 일제사 공통 오차를 줄이고, 실제 관측한 단발 탄착을 다음 사격에 조금씩 반영합니다. 급탄·포신·포탑 인력 손상은 해당 포의 사격을 제한하며, 운용 명령은 진행 중인 개별 장전에도 적용됩니다. 화면에는 포별 장전 잔여 시간과 준비 상태가 표시됩니다.

v17은 실제 내부 관통에 도달한 강한 피탄이 설비·인력·구획 구조를 더 빨리 손상시키는 빠른 결착 게임 조정입니다. 도탄과 스침은 같은 증폭을 받지 않습니다. 주증기·운용 인력 상실은 발전과 전동 급탄 중단으로 이어지며, 추진·급탄이 함께 무너지면 빠르게 전투 불능이 됩니다. 기동은 확대된 표시 선체에 맞는 최소 선회 반경과 타력·선회 감속을 사용하고, 노트 속도와 위치·탄도는 계속 같은 거리 환산을 따릅니다. 회피 표시는 적이 발사할 때 사용한 속도·선회 예측과 현재 위치의 차이를 미터로 보여줍니다. 함대 추적 카메라의 줌 변화도 완만하게 처리합니다.

v18은 초기 조우 거리와 이후 거리 운용을 구분합니다. **교전 거리 유지**는 상대의 위치와 현재 간격을 보고 항로를 보정하며, 지그재그도 그 목표 거리 주변에서 수행합니다. 42 km 조우는 양함이 포격할 수 있는 약 36 km까지 접근한 뒤 원거리를 유지합니다. **접근하며 교전**을 선택하면 6 km를 목표로 접근합니다. 선회·관성·추진 손상 때문에 목표 거리는 순간 고정값이 아닌 기동 목표입니다. 같은 프리셋을 여러 탭에서 열면 가장 최근에 연 탭이 저장을 담당하고, 이전 탭은 새 설정을 덮어쓰지 않습니다.

v19는 공통 조준 오차를 실제 거리의 미터 단위로 계산합니다. 표시용 선체 확대 비율로 오차가 수 km로 커지던 문제를 줄이며, 시정·사격통제·기동과 관측한 탄착의 보정은 계속 반영합니다. 기본 시작은 **24 km 맞포격**, 장거리 조우는 양함이 사격 가능한 **36 km**입니다. 과거 42 km 저장 교전은 기존 버전으로 재현합니다. 피해·관통 모델과 물리적인 탄착 판정은 바꾸지 않습니다.

v20은 새 교전의 거리 축척을 고정합니다. 6·12·18·24 km를 골라도 화면의 시작 간격이 같던 문제를 고쳐, 시작 거리가 멀수록 실제 3D 배치도 벌어집니다. 이동·조준·탄도·충돌 판정은 같은 좌표 축척을 사용합니다. 함선은 계속 디테일을 위한 확대 모형이며, 달라진 상대 크기와 간격으로 새 교전의 명중·피해 결과는 이전 버전과 달라질 수 있습니다. v19 이하 저장 교전은 기존 배치와 계산을 그대로 재현합니다.

v21의 **SF 방어 실드**는 별도로 선택하는 게임 모드입니다. 움직이고 흔들리는 함선 주위의 타원체 경계를 실제 포탄의 자유 비행 경로와 연속 판정합니다. 최초 실드 접촉에서 포탄은 공중 기폭하고, 해당 발의 선체 피탄·관통·침수는 발생하지 않습니다. 포탄의 질량과 충돌 순간 속도로 계산한 운동에너지가 실드의 900 MJ 방어 용량을 소모하며, 용량을 넘긴 마지막 탄은 실드를 붕괴시킵니다. 이후 탄은 기존 선체 충돌 판정을 사용합니다. 자동 재충전은 없으며, 방어장은 아군 포탄을 내보낼 수 있다는 SF 규칙을 사용합니다. 실드의 물성·기폭·방어 용량과 파편 연출은 게임용 가정입니다.

충돌 지점의 섬광·파문·분기 균열, 퍼져 나가는 육각 실드 파편, 백색 압력 섬광과 주황색 고온 가스·검은 연무가 이어집니다. **실드 붕괴 슬로모션**은 실제 교전에서 계산된 첫 붕괴 지점으로 이동해 0.25×로 재생합니다. 별도의 가짜 선체 피해를 만들지 않으며, 일시정지·시간 되감기에서도 같은 시점의 효과가 재현됩니다. 일반 함포전과 v20 이하 저장 교전은 기존 계산을 유지합니다.

**v22 일반 교전 / v23 SF 실드 교전**은 함선과 거리를 같은 실제 축척으로 계산합니다. [야마토박물관의 전장 263 m](https://yamato-museum.com/yamato-data/)를 모델의 선체 길이 110에 대응시켜, 6 km 중심 간 거리는 야마토 선체 약 **22.81척 길이**, 24 km는 약 **91.25척 길이**가 됩니다. 아이오와 모델의 선체는 이 축척에서 약 269.2 m이며, [미 해군 기록의 887 ft 3 in / 270.43 m](https://www.history.navy.mil/research/histories/ship-histories/danfs/i/iowa-iii.html)에 대한 약 0.45% 근사입니다. 속력·포구·탄도·피탄·실드 경계도 이 축척을 공유합니다. 함선 확대는 카메라만 이동하며, 모델과 충돌 경계의 크기는 그대로입니다.

**실제 거리 전체 보기**는 양함을 위에서 보고 1 km 큰 눈금과 야마토 한 척 길이(263 m)의 작은 눈금을 표시합니다. 바다 범위와 카메라 클리핑도 먼 거리 교전에 맞춰 확장했습니다. 전체 화면에서 함선이 작아지는 것은 거리 대비 실제 크기를 반영한 결과이며, 디테일은 **함선 확대**로 볼 수 있습니다. v9~v21 저장 교전은 이전 좌표와 계산으로 재생하며, 새 교전부터 실제 축척을 적용합니다.

화면 바로 위의 **관찰 카메라**에서 시점을 바꿀 수 있습니다. **자유 관찰**은 직접 회전·확대하고, **교전 관찰**은 선택한 함선 가까이에서 적을 향한 포격을 봅니다. **함선 추적**은 함선 가까이에서 포구 너머 실제 적함을 함께 담는 낮은 구도로 따라가고, **탄착 추적**은 그 함선으로 날아오는 포탄과 탄착을 관찰합니다. 먼 거리의 적함은 실제 축척대로 작고 흐릿하게 보이며, 이름·거리 표시가 실제 위치를 가리킵니다. 예측 조준점은 탄도 보기에서 별도로 표시합니다. 카메라 선택은 함선 크기·거리·탄도·피격 판정이나 전투 결과를 바꾸지 않습니다. 자동 관찰 중 화면을 드래그하면 자유 관찰로 전환합니다. 모바일에서도 이 선택은 접힌 설정 밖에 표시됩니다.

자동 관찰 중에는 휠과 **줌 − / 줌 +** 버튼으로 확대·축소해도 함선 추적을 유지합니다. **기본 구도**는 선택한 관찰 모드의 기본 확대율로 돌아갑니다. 함선 확대 화면 오른쪽 위에는 같은 전투의 **상대 함선 확대 보기**를 함께 표시하고, 누르면 그 함선으로 관찰 대상을 바꿉니다. 이 보조 화면은 별도 카메라로 현재 시간의 실제 함선과 효과를 가까이 보여주며, 함선 모델이나 교전 거리를 확대하지 않습니다.

자유 관찰로 카메라를 돌릴 때도 교전 거리에 맞는 안개 가시거리를 유지합니다. 원거리 적함의 화면 높이가 5픽셀 미만이면 실제 함선 윗부분 위치에 3픽셀 접점을 더해 식별을 돕습니다. 접점은 깊이·안개 처리를 따르므로 앞쪽 선체나 바다에 가려지고, 화면 밖·침몰·내부 구획·유폭 미리보기에서는 표시하지 않습니다. 함선 크기나 물리 판정은 바뀌지 않습니다.

주포 발사에는 포구에서 나온 공기 압력이 해면을 누르고 흐트러뜨리는 연출도 연결합니다. 실제 발사 시점과 방향에서 시작한 낮은 물안개·거품과 작은 파문이 잠깐 번지고 사라지며, 시간을 되돌려도 같은 위치와 나이로 재현합니다. 해면의 국소 변위와 반사 변화는 화면용 근사이며 유체역학 압력 해석은 아닙니다. 함선의 파도 운동·탄도·피격 판정에는 영향을 주지 않습니다.

초속 기준은 야마토 AP **780 m/s**, 일반탄(HE 근사) **805 m/s**, 아이오와 AP **762 m/s**, HC(HE) **819.9 m/s**입니다. 근거는 당대 [미 해군 야마토 조사 O-45(N), 16~17쪽](https://www.fischer-tropsch.org/primary_documents/gvt_reports/USNAVY/USNTMJ%20Reports/USNTMJ-200F-0384-0445%20Report%20O-45%20N.pdf)과 [아이오와 OP1188 사거리표, 61~62쪽](https://www.eugeneleeslover.com/ENGINEERING/OP1188/OP1188_Abridged_Range_Tables_1944.pdf)입니다.

## 실행

이 폴더에서 아래 명령을 실행하고 [로컬 화면](http://localhost:8080)을 열면 됩니다.

```sh
python3 -m http.server 8080
```

`index.html`은 한국어 소개 화면, `en.html`은 영어 소개 화면, `simulator.html`은 함포전 화면입니다. 화면 상단에서 한국어와 영어를 선택할 수 있으며, 플레이 URL의 `lang=ko` 또는 `lang=en`으로 언어를 지정할 수 있습니다. WebGL을 지원하는 최신 데스크톱 브라우저를 권장합니다. 실행에는 npm 설치나 빌드가 필요하지 않습니다.

플레이 중에는 GPT 모델을 호출하지 않습니다. API 키, 로그인, 별도 게임 서버나 데이터베이스도 필요하지 않습니다. Three.js r128과 OrbitControls를 사용하는 정적 HTML·JavaScript 프로젝트이며, 실행 상태는 브라우저 안에서 처리합니다. 외부 CDN 의존성이 남아 있는 배포본은 최초 로딩에 인터넷 연결이 필요합니다.

### 시작 장면

| 주소 | 첫 진입 시 장면 |
| --- | --- |
| `simulator.html?preset=duel` | 24 km 맞포격의 시작, 4× 재생 속도 |
| `simulator.html?preset=battle` | 6 km 근거리 교전의 시작, 4× 재생 속도 |
| `simulator.html?preset=blast` | 실제 교전에서 발생한 탄약고 유폭 직전, 0.25× 슬로모션 |
| `simulator.html?preset=maximum` | 36 km에서 양함 사격권의 장거리 조우, 4× 재생 속도 |
| `simulator.html?preset=he` | 양측 고폭탄을 사용하는 6 km 교전, 1× 재생 속도 |
| `simulator.html?preset=shield` | SF 실드가 켜진 6 km 고폭탄 교전, 첫 실제 실드 붕괴 직전의 0.25× 재생 |
| `simulator.html?preset=preview` | 소개 화면에 쓰는 야마토 외관 미리보기 |

소개 화면의 기본 시작 버튼은 **24 km 맞포격**입니다. 36 km 장거리 교전, 6 km 교전과 유폭 장면은 별도 링크로 열 수 있습니다. 새 시작 링크의 `fresh=1`은 이전 저장 상태를 건너뛰고, 로딩 후 주소에서 제거됩니다. 이후 새로고침은 현재 전투를 복원하며, **저장한 교전 이어 보기**도 사용할 수 있습니다. 프리셋을 생략하면 24 km 맞포격으로 시작합니다.

전투 화면은 일시정지 상태로 열립니다. **현재 교전 계속**은 현재 전투를 이어 갑니다. 거리·시정·기동·정비·유폭·명중률 조건을 바꾸면 적용 대기 안내가 표시되며, **선택한 설정으로 새 교전**이나 **새 교전**으로 현재 선택값과 새 시드를 적용합니다. **현재 교전 다시보기**는 현재 적용된 조건과 시드를 유지합니다. 파도·재생 속도·시점·피해 구획·탄도 표시는 즉시 바뀝니다. 적용 대기 중인 조건도 새로고침과 언어 전환 후 유지됩니다.

모바일에서는 재생 버튼과 함선 화면이 먼저 나오고, 교전 설정·함선 운용·화면 효과·함선 상태를 필요한 때 펼칩니다. 설정은 거리·기동, 탄종·조준, 손상·정비로 묶고 좁은 화면에서는 한 열로 표시합니다. 적용 대기 표시와 설정 적용·교전 복귀 버튼은 접힌 메뉴 밖에서도 사용할 수 있습니다. 넓은 화면에서는 전체 옵션이 펼쳐집니다.

저장된 v9~v21 교전은 각 버전의 기존 피해·탄도·항로 계산으로 복원·재생합니다. **새 교전** 또는 **선택한 설정으로 새 교전**을 누르면 일반 모드는 v22, SF 실드 모드는 v23의 실제 거리 축척으로 시작합니다. 거리 기반 조준·거리 운용·취약 구획·개별 함포 사격·운용·탄도 모델을 함께 사용합니다.

## 소스 수정과 재생성

함선 모델과 전투 로직은 `source/simulation.html`, 독립 실행 화면과 상태 저장은 `source/player-template.html`에 있습니다. 이를 수정한 뒤 이 폴더에서 아래 명령을 실행합니다.

```sh
python3 tools/build.py
```

Python 표준 라이브러리만 사용해 `simulator.html`을 재생성합니다. 생성된 파일을 직접 수정하면 다음 재생성 때 덮어씁니다. 소개 화면은 `index.html`, `en.html`과 `assets/site.css`에서 수정합니다. 소스를 바꿨을 때는 재생성한 `simulator.html`도 함께 커밋합니다.

영문 문구는 `assets/simulation-en.json`, 화면 번역 처리는 `source/simulation-i18n.js`에서 관리합니다. 언어 전환은 재생 중에도 전투와 시점을 유지하며, 언어별로 같은 프리셋의 저장 상태를 공유합니다.

공개 화면의 현재 조건·설정 적용·초안 저장 처리는 `source/public-controls.js`에서 관리하며 빌드가 원본 시뮬레이터의 실행 구간에 삽입합니다.

모바일 배치와 접힘 메뉴는 `source/public-responsive.js`, 터치 영역과 반응형 스타일은 `assets/simulator-responsive.css`에서 관리합니다. 화면 크기가 바뀌면 기존 조작 요소를 이동하므로 선택값과 이벤트 연결을 유지합니다.

## GitHub Pages로 공개

1. 이 폴더의 소스를 `main` 브랜치에 보관합니다.
2. `index.html`, `en.html`, `simulator.html`, `robots.txt`, `sitemap.xml`, `.nojekyll`, `assets/`를 `gh-pages` 브랜치 루트에 올립니다.
3. 저장소의 **Settings → Pages → Build and deployment → Source**에서 **Deploy from a branch**, 브랜치는 **gh-pages**, 폴더는 **/(root)**를 선택합니다.
4. 배포가 끝나면 **Settings → Pages**에서 플레이 URL을 확인합니다. 이후 공개 파일을 바꿔 `gh-pages`에 푸시하면 갱신됩니다.

웹사이트에는 `gh-pages`의 공개 파일만 올라갑니다. README와 편집 소스는 `main`에서 읽을 수 있습니다. 추가 공개 리소스는 `assets/`에 둡니다. `.nojekyll`은 정적 HTML을 그대로 제공하도록 합니다.

설정 방식은 [GitHub Pages의 게시 소스 안내](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)를 따릅니다. 사용자 정의 Actions 워크플로 없이 GitHub Pages의 기본 배포 기능을 사용합니다.
